## 2. 资源 API

根路径：`/api/ai/conversations`

| 方法 | 路径 | 成功响应 |
| --- | --- | --- |
| POST | `/api/ai/conversations` | HTTP 201 + Conversation |
| GET | `/api/ai/conversations?status=&cursor=&limit=` | Conversation Page |
| GET | `/api/ai/conversations/{conversationId}` | Conversation |
| GET | `/api/ai/conversations/{conversationId}/messages?beforeSequence=&limit=` | Public Message Page |
| POST | `/api/ai/conversations/{conversationId}/archive` | Conversation |
| POST | `/api/ai/conversations/{conversationId}/restore` | Conversation |
| DELETE | `/api/ai/conversations/{conversationId}` | `{ "deleted": true }` |

冻结响应字段：

- Conversation：`conversationId/title/status/createdAt/updatedAt`；
- Conversation Page：`items/nextCursor/hasMore`；
- Public Message：`messageId/conversationId/sequence/role/messageType/content/traceId/toolCallId/metadata/createdAt`；
- Message Page：`items/nextBeforeSequence/hasMore`；
- Delete：`deleted=true`。

时间字段在 DTO 层显式转换为 ISO-8601 字符串，不依赖全局 Jackson 时间序列化选项。

## 3. 授权和不存在语义

- Controller 的每个端点都调用 `RequestUserContext.getRequiredUserId()`，并只把该值传给资源服务；
- DTO 中不存在 `userId` 或管理员授权字段；创建请求里的未知 `userId/admin` 被忽略，列表/详情中的同名额外查询参数不参与授权；
- 没有 `isAdmin()` 分支，没有跨用户读取、归档、恢复或删除入口；
- 有效格式但不存在、已永久删除或属于其他用户的 Conversation 均由 M02 服务统一返回 `CONVERSATION_NOT_FOUND`；
- 未认证的 Controller 调用使用真实 HTTP 401 + `AUTHENTICATION_REQUIRED`。Spring Security 入口本身仍由现有全局安全配置负责。

## 4. 游标契约

`ConversationCursorCodec` 只编码冻结的两个 seek 字段：

```text
updatedAt + conversationId
```

令牌使用：

- 版本化载荷；
- 无填充 Base64URL；
- 域隔离的 HMAC-SHA256；
- 常量时间签名比较；
- 规范编码复核、长度、版本、时间和 Conversation ID 校验。

非法、篡改、异密钥或非规范 cursor 均返回：

```text
HTTP 400
{"errorCode":"INVALID_CONVERSATION_CURSOR","message":"Conversation cursor is invalid"}
```

配置优先级：

1. `AI_MEMORY_CURSOR_SIGNING_KEY`；
2. 现有 `OMNIDOC_JWT_SECRET`（经游标专用域派生，不直接复用 HMAC key）；
3. 两者均为空时使用域隔离、跨重启稳定的本地开发回退值。

生产多副本仍要求显式提供私有共享密钥；固定回退只保证本地功能稳定，不把游标签名当成授权边界。每次查询仍由认证所有者过滤，非法 cursor 不会回退第一页。

## 5. 公开消息边界

`ConversationPublicMessageMapper` 是拒绝优先投影，只允许：

- USER + TEXT；
- ASSISTANT + TEXT；
- TOOL + EVENT + `metadata.displayable=true`。

明确排除：

- 所有 SYSTEM；
- TOOL_CALL；
- TOOL_RESULT；
- `displayable=false` 或未显式批准的 TOOL EVENT；
- durable message 的 turn/clientRequest/contentHash 和内部 metadata；
- 工具事件的原始 content，包括完整工具结果、参数或审批信息。

公开工具事件正文只从白名单 `label/toolName/status` 重建；公开 metadata 只允许 `displayable/eventType/label/status/toolName` 的字符串或布尔值，并清理控制字符和限制文本长度。USER/ASSISTANT 的 metadata 固定为空对象。

当前分页保持 M02 原始 sequence seek 语义：存储层页内先按 sequence 升序返回，再做公开投影。因此某页可能因内部消息被过滤而少于请求 limit，甚至为空，但 `nextBeforeSequence/hasMore` 仍能继续遍历，不会为了凑满公开条目扩大一次数据库读取或改变 M02 存储语义。

## 6. 错误载体

结构化 API 使用专用高优先级 Advice，返回真实 HTTP 状态和顶层：

```json
{
  "errorCode": "CONVERSATION_NOT_FOUND",
  "message": "Conversation was not found"
}
```

稳定映射：

| errorCode | HTTP |
| --- | --- |
| `CONVERSATION_REQUEST_INVALID` | 400 |
| `INVALID_CONVERSATION_CURSOR` | 400 |
| `AUTHENTICATION_REQUIRED` | 401 |
| `CONVERSATION_NOT_FOUND` | 404 |
| `CONVERSATION_ARCHIVED` | 409 |
| `CONVERSATION_CONFLICT` | 409 |
| `MEMORY_PERSISTENCE_DISABLED` | 503 |
| `CONVERSATION_REQUEST_FAILED` | 500 |

该 Advice 只绑定 `ConversationController`，没有改变旧 `/api/ai/agent/chat/**` 的 HTTP 200 + `Result` 兼容格式。这样 M06-A 前端可以从非 2xx 响应的 `response.data.errorCode` 保留稳定业务码，不受现有 200 业务错误拦截逻辑影响。
