## 2. 交付行为

- 新增 `useConversationWorkspace`，统一活动/归档列表、稳定分页、详情恢复、公开消息分页、新建、归档、恢复、永久删除和提交生命周期；
- Global Assistant 与 Editor 都按认证用户和入口隔离活跃指针、草稿和 pending `clientRequestId`；不再读取默认用户；
- 刷新后从结构化 API 恢复 Conversation 和 durable 消息；公开投影造成空页时继续翻页，旧消息按 sequence 去重并前置；
- “新对话”先完成真实后端创建再切换；创建失败保留原指针和草稿，不生成 `temp_*`，不使用 `default_conv`；
- Agent 请求携带真实 `conversationId` 与安全 UUID `clientRequestId`；失败保留草稿，不向历史写入本地伪 assistant 回答；
- 两个入口都提供活动/归档会话选择、列表继续分页、消息向前分页、归档/恢复和二次确认永久删除；永久删除后清理活跃指针、消息、草稿和 pending 提交；
- 会话切换使用请求代次，保证最后一次激活操作获胜；新建、归档、恢复和删除会使更早的详情请求失效；执行/确认生命周期中禁止切换或删除；
- 并发加载状态使用计数，旧请求结束不会提前清除新请求的 loading 状态；
- 过期、损坏或缺少所有者的 JWT 在路由层清理本地认证状态并返回登录页，组件不再使用 `localStorage.userId` 作为授权作用域；
- 原 `useGlobalAi` 只保留面板显示状态，Conversation 事实和历史不再保存在旧全局单例。

## 3. 回归翻转

M01 的三份前端测试原用于证明刷新不恢复、临时 ID、`default_conv` 和只清 UI 等缺陷。M06-C 已将它们翻转为目标回归，覆盖：

- 旧全局单例不再持有 Conversation 事实；
- Global Assistant 刷新恢复 durable 历史；
- 创建失败不执行 Agent 且保留草稿；
- Editor 新建真实 Conversation 后才发送；
- Editor 创建失败不使用默认 ID；
- 生产代码继续拒绝 `temp_*` 与 `default_conv`。

## 5. 未验证项与剩余风险

- 当前 `agentApi.executeTask` 在单次页面生命周期内提交并轮询异步 `jobId`；前端会复用 `clientRequestId`，但尚未把已提交的 `jobId` 持久化用于刷新后恢复轮询。“提交成功、轮询丢失、刷新后重试”必须在真实链路验收中单独验证，当前不能声称断线恢复已完成；
- 结构化 API 的 201/200/非 2xx、JWT 过滤器、跨用户统一 404、服务重启后的 cursor 和 MySQL 回源尚未由真实浏览器联调验证；
- 公开工具历史只显示 M06-B 批准的 EVENT 投影，完整工具结果不会因刷新重新暴露；当前页面的可下载操作卡属于短期 UI 状态；
- 构建仍有主 JS chunk 超过 500 kB 的既有警告；本任务未做无关拆包；
- 完整 M07、真实外部依赖和用户人工验收通过前，Memory V1 仍不得写为最终通过。
