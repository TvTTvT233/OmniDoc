## 2. 生产骨架

### 2.1 统一 API

文件：`web/src/api/conversation.js`

提供：

- `createConversation`
- `listConversations`
- `getConversation`
- `listMessages`
- `archiveConversation`
- `restoreConversation`
- `deleteConversation`

所有路径使用 `/ai/conversations`，由现有 request 的 `/api` baseURL 组成冻结的 `/api/ai/conversations` 资源。API 不接收或转发客户端 `userId`；创建只允许受控 `title`，列表只允许 `status/cursor/limit`，消息分页只允许 `beforeSequence/limit`。

### 2.2 DTO 与错误边界

文件：`web/src/api/conversationContract.js`

前端 DTO 冻结为：

- Conversation：`conversationId/title/status/createdAt/updatedAt`；
- Conversation Page：`items/nextCursor/hasMore`；
- Public Message：`messageId/conversationId/sequence/role/messageType/content/traceId/toolCallId/metadata/createdAt`；
- Message Page：`items/nextBeforeSequence/hasMore`；
- Delete Result：`conversationId/deleted`。

公开消息边界只允许 USER/ASSISTANT 文本和明确 `displayable=true` 的 TOOL EVENT；SYSTEM、TOOL_CALL、TOOL_RESULT 及未批准 metadata 不进入前端 DTO。错误规范化保留冻结的稳定服务端代码；未知错误归一为 `CONVERSATION_REQUEST_FAILED`，非法响应归一为 `CONVERSATION_RESPONSE_INVALID`。

### 2.3 会话状态 composable

文件：`web/src/composables/useConversationSession.js`

模块名：`useConversationSession`。

- 要求调用者提供非空认证 `userId` 和冻结入口 `global-assistant/editor`，无默认用户；
- 活跃指针保存在按 `userId + entry` 隔离的 `localStorage` key；
- 草稿和待重试提交保存在按相同作用域隔离的 `sessionStorage` key；
- `createAndActivate` 只在后端创建成功后切换指针；失败保持旧指针和草稿；
- 明确拒绝 `temp_*` 与 `default_conv`；
- `beginSubmission` 生成安全 UUID `clientRequestId`；失败重试及同一标签页刷新复用同一 UUID；
- 草稿内容或活跃 Conversation 改变时废弃旧 pending ID；成功提交后才清除草稿和 pending ID；
- 浏览器存储不可用时只降级为当前页面内存状态，不伪造 Conversation。

## 6. 剩余风险和集成要求

- M02 与结构化 Controller 尚在并行开发，本任务的 HTTP 请求只通过 mock 验证，真实响应字段和错误载体必须在协调集成时对齐；
- 新状态模块尚未接入旧 UI，因此现有 `temp_*`、`default_conv` 和旧刷新行为仍由 M01 基线准确复现；不能把新模块存在描述为用户行为已经修复；
- M06-B/M06-C 仍需接入列表、消息分页、路由恢复、归档/恢复、二次确认删除和异常 UX；
- 当前 request 拦截器对 HTTP 200 内的非成功业务响应可能丢失结构化错误 code；结构化后端应使用协调后可验证的稳定错误载体，集成测试必须覆盖；
- `npm ci` 仍报告 12 个依赖审计问题（3 moderate、7 high、2 critical），未执行破坏性 `audit fix`；
- 构建仍有主 JS chunk 超过 500 kB 的既有警告；
- 没有真实鉴权、多用户、浏览器刷新或后端持久化证据，完整 M06 和 M07 保持 `PENDING`。
