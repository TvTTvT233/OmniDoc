# Memory V1 M02：Conversation/Message 持久化交接

## 1. 状态与边界

```text
HANDOFF_READY / H2_MYSQL_MODE_VERIFIED / REAL_MYSQL_PENDING
```

- 分支：`feature/memory-m02-persistence`；
- 基线：`ac1033bc3a0f9437b2833f08449e6d001070c0a6`；
- 交付提交：本文件所在提交；精确 SHA 由协调任务挑选时记录；
- 所有权：`ai-service` Conversation/Message domain、store、service、Memory Schema、`ConversationManager` 兼容门面及专项测试；
- 未修改：`AgentExecutionService`、`ContextManager`、`AgentController`、`web/**`、Summary、Runtime State、Context Builder。

本交付实现 M02 持久化能力，不声明 M03-M07、完整 Memory V1、真实 MySQL 集成或人工验收已经完成。

## 2. 已实现

- 新增结构化 `Conversation`、`ConversationMessage`、角色、消息类型、分页模型及稳定领域错误；
- 使用 Spring JDBC 和 MySQL Driver，不引入 ORM；
- 新增 `ai_conversation`、`ai_conversation_message`、`ai_memory_schema_version` 专属表和 `V001` 幂等 SQL；没有创建 M05 才拥有的 Summary 表；
- `MemorySchemaInitializer` 在 `ai.memory.enabled=true` 时执行启动校验；自动迁移仅由 `ai.memory.schema.auto-migration.enabled=true` 显式开启，关闭且表/版本缺失时启动失败，不回退 Redis；
- 消息 sequence 在锁定 Conversation 行的同一数据库事务中分配并插入，数据库唯一约束保护 `conversation_id + sequence`；
- 使用 `conversation_id + client_request_id + role + message_type + turn_ordinal` 实现重试幂等；同一幂等键复用不同内容、工具关联或 metadata 时返回冲突；
- 每次读、写、归档、恢复和删除均校验所有者；不存在和跨用户访问统一为 `CONVERSATION_NOT_FOUND`；
- 支持稳定 Conversation cursor 分页、Message `beforeSequence` 分页、归档、恢复和物理级联删除；归档状态禁止追加；
- Message metadata 使用字段和类型白名单，不接受认证 Header、未限长对象或未知字段；内容保存 SHA-256；
- 旧 `conv:*` 仅在 `ai.memory.legacy.import.enabled=true` 时按需读取；先校验 Redis owner，只严格解析 `User: ` / `Assistant: `，其他条目保存为 `EVENT` 并标记 `legacyImported/legacyUnparsed`；导入写 MySQL且重复读取不重复生成消息；
- 新 Conversation/Message 只写 MySQL，不双写旧 Redis 字符串列表；`ctx:*` 未导入；
- `ConversationManager` 保留 start/history/end、列表、所有者检查和 Agent 末尾消息对写入所需签名，但内部只委托新 Service；无认证用户参数的旧方法明确拒绝执行；
- JDBC 启用后，MySQL 用户名/口令占位符具有空默认，`AllModelsTest` 显式关闭 Memory 启动校验；普通单元测试和该测试不会因 M02 自动连接真实 MySQL。

## 3. 配置

```yaml
ai:
  memory:
    enabled: true
    schema:
      auto-migration:
        enabled: false
    legacy:
      import:
        enabled: false
```

- `AI_MEMORY_ENABLED` 默认 `true`；
- `AI_MEMORY_SCHEMA_AUTO_MIGRATION_ENABLED` 默认 `false`，生产/共享数据库建议先人工审阅并应用 SQL；
- `AI_MEMORY_LEGACY_IMPORT_ENABLED` 默认 `false`，只在明确兼容窗口开启；
- Memory 启用而 Schema 未准备时是明确启动失败，不是 Redis 降级。

## 5. 剩余风险与后续要求

- 未连接真实 MySQL；SQL 已在 H2 `MODE=MySQL` 验证，但真实 MySQL 8 的 DDL、锁等待、字符集、时区和并发行为必须由集成任务复核；
- 未运行完整 `ai-service`、真实 Redis 导入、真实服务重启、浏览器、真实模型、MCP、Qdrant 或端到端；
- 按任务边界未修改 `AgentExecutionService`，因此“USER 消息在模型调用前提交”和逐个 TOOL/EVENT 产生即写入尚未接入 Agent 主链；M02 Store/Service 已提供结构化追加能力，接入由后续协调任务按冻结顺序完成；
- M03 才负责删除 Runtime State、任务快照和审批引用；本任务只保证 MySQL Conversation -> Message 级联删除；
- M05 才创建和清理 Summary；本任务没有伪造 Summary 存储；
- 旧 Redis 数据自然过期时无法恢复；兼容导入默认关闭，开启窗口、迁移计数汇总和结束策略需要部署协调；
- 默认 Memory 已启用且自动迁移关闭，部署前必须先应用 `db/memory/V001__conversation_message.sql`，否则服务会按契约明确启动失败。
