## 已实现

### 受控模型与隔离

- 新增 `conversation.runtime` 包，Runtime State 与长期 Conversation Memory 分离；
- 存储作用域必须同时提供 `conversationId + traceId`，Redis 键对两个 ID 分别编码；
- Runtime State 更新使用 typed DTO，不提供任意 `Map` 扩展入口；
- 冻结白名单只有以下五项：

| 字段 | 生命周期 | 默认/硬上限 TTL | 默认/硬上限大小 |
| --- | --- | --- | --- |
| `currentDocumentId` | 滑动；读取后刷新 | 30 分钟 | 512 UTF-8 bytes |
| `selectedText` | 当前 turn 消费后删除 | 10 分钟 | 16 KiB |
| `pageContext` | 当前 turn 消费后删除 | 10 分钟 | 4 KiB |
| `pendingApproval` | 不超过引用有效期 | 5 分钟 | 1 KiB |
| `currentToolState` | trace 结束时清理 | 1 小时 | 2 KiB |

- 配置只允许收紧 TTL/大小，不能放大冻结硬上限；生产与 local 配置均提供显式安全默认值；
- `pendingApproval` 只允许 typed 非敏感引用，不含审批令牌字段；`currentToolState` 只允许调用 ID、工具名、阶段和短状态，不含工具结果；
- Redis 值使用严格版本化 JSON 字符串 envelope，拒绝 Redis 中的任意 Map、额外字段和非受控类型；页面/工具状态额外拒绝 credential/token 特征文本。

### 生命周期与清理接口

- `readRequired`：审批、一次性输入或 trace 续接需要状态时使用；Redis 不可用抛出稳定错误 `RUNTIME_STATE_UNAVAILABLE`；
- `readOptional`：普通请求可无 Runtime State 继续时使用；Redis 不可用返回 `DEGRADED_UNAVAILABLE + empty snapshot`，不会把降级伪装成正常空状态；
- `consumeTurnInput`：对 `selectedText/pageContext` 分别执行读取即删除；两项不组成跨键事务；
- `clearFields`：只接受字段枚举；
- `clearTrace`：删除一个 `conversationId + traceId` 的全部五类状态；
- `clearConversation`：通过受控 trace 索引删除 Conversation 下所有 Runtime State，同时删除旧 `ctx:*`；该接口留给 M02 删除协调器后续接入。

### 旧 `ctx:*` 兼容

- 旧 Hash 只读 `currentDocumentId`（兼容别名 `documentId`）、`selectedText`、`pageContext` 三个 bounded scalar；
- 明确忽略 `documentContent`、`approvalToken`、`pendingApproval` Map、`currentToolState` Map、`lastToolResults` 和任意其他字段；
- 每次兼容读取为旧键设置 10 分钟 TTL，配置硬上限 30 分钟；
- 旧数据没有 trace，故不导入新的 trace-scoped store，也没有任何 Summary 依赖或导入路径；
- `ContextManager` 已成为兼容适配器：旧 Map 写入只提取带 `traceId` 的三个白名单标量；无 trace 写入不持久化，单字段无 trace 写入直接拒绝。
