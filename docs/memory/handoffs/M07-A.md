## 2. 交付内容

### M02 持久化阶段门禁

- `scripts/memory/run-m02-gate.ps1/.cmd`
- 默认模式只做门禁资产自检；
- `-Integrated` 检查 Conversation model/store、`MemorySchemaInitializer`、Spring JDBC 与 MySQL Driver；
- 就绪后固定运行 `MemoryV1ExpectedContractTest`、M02 persistence/store/schema 专项通配和 `AgentExecutionServiceTest + AgentControllerTest`；
- 逐名要求以下四个冻结目标 testcase 存在并且 skipped 为 0：
  - `m02PersistsStructuredMessagesWithMonotonicSequence`
  - `m02RetriesDoNotDuplicateUserOrAssistantMessages`
  - `m02HistorySurvivesServiceRestartAndRedisExpiry`
  - `m02ConversationAccessIsOwnerIsolated`
- 生产资产、测试方法或执行证据缺失时生成 `PENDING_INTEGRATION` 阶段报告并非零退出。

报告路径：

```text
ai-service/target/memory-v1-acceptance/memory-m02-stage-report.json
```

### M06-A 前端契约阶段门禁

- `scripts/memory/run-frontend-contract-gate.ps1/.cmd`
- 默认要求 `web/src/api/conversation.js`、实际维护 `conversationId` 的会话状态模块和 `test:memory-contract`；
- 合理的不同文件或脚本名可以通过 `-ConversationApiPath`、`-ConversationStatePath`、`-FrontendTestScript` 显式指定；
- `-Integrated` 运行前端 contract tests，并要求至少发现 1 项、skipped 为 0；
- 同时运行 `AgentExecutionServiceTest + AgentControllerTest` 回归；
- 该门禁不要求后端结构化 Conversation API 已实现，不把 M06-A 误报为完整 M06-B/C。

报告路径：

```text
ai-service/target/memory-v1-acceptance/memory-m06a-frontend-stage-report.json
```

## 4. 集成使用顺序

1. M02 合入后运行 `run-m02-gate.cmd -Integrated`；只有四个 M02 目标 skipped=0 且专项与 Agent/Controller 回归均通过时才允许 `STAGE_VERIFIED`。
2. M06-A 合入后运行 `run-frontend-contract-gate.cmd -Integrated`；它可以独立于后端结构化 API 验证前端契约骨架。
3. M06-A 通过后，完整 `run-m07-acceptance.cmd -Integrated` 仍必须保持 `PENDING_INTEGRATION`，直到 M03-M06 和最终 M07 gate 全部存在并通过。
4. 最终 M07 必须重新执行冻结的全部 P0/P1、目标 skipped=0、回归、资源清理和报告一致性检查，阶段报告不得直接晋升为最终报告。

## 5. 剩余风险

- 当前没有 M02/M06-A 生产实现，因此只验证了资产成功路径与实现缺失的 PENDING 路径，尚未执行阶段 `STAGE_VERIFIED` 路径。
- 未连接真实 MySQL、Redis、浏览器、模型、远程 Embedding 或 Qdrant；报告对应边界均保持 false/0。
- M02 门禁以冻结的四个 `MemoryV1ExpectedContractTest` 方法为不可跳过目标；后续任务若重命名，必须同步更新门禁并说明契约迁移，不能删除目标以规避检查。
- M06-A 前端计数依赖 Vitest JSON reporter；若测试框架发生明确变更，需要更新报告适配器，但仍必须保留发现数、失败数和 skipped=0 门禁。
- Windows PowerShell 在当前调用宿主中把脚本显式 `exit 2` 呈现为实际进程退出码 1；门禁依赖的是“非零即未通过”，不依赖某个特定非零值。
