## 文档优先级

1. 用户对 M0-00 明确确认的边界；
2. `docs/requirements/SCHOLARSHIP_REVIEW_V1.md`；
3. `docs/OMNIDOC_CONTEXT.md`；

## 术语

| 术语 | 唯一含义 |
| --- | --- |
| 官方依据 | 用户上传并手动分类为申报通知、填写说明或官方模板的文件 |
| 候选清单 | 从官方依据提取、尚未由用户确认的可编辑材料要求集合 |
| 正式清单 | 用户确认后形成的不可变清单快照；正式审查只能引用该快照 |
| 提交材料 | 用户声明用于满足正式清单项目的文件；ZIP 内每个合法叶子条目是一个材料单元 |
| `submissionFileName` | Review M0 使用和下载时呈现的逻辑叶子文件名，不是原始文件名或对象键 |
| 材料集合证据 | 对某次用户“上传完毕”确认所覆盖的完整材料清单、分配和摘要的不可变快照 |
| 确定性结论 | `MISSING` 或 `FILE_NAME_NONCOMPLIANT`；必须同时有规则证据和材料/材料集合证据 |
| `CANNOT_CONFIRM` | 信息或材料不可可靠处理，不是缺失结论，也不是系统错误的包装 |
| `M0_READY` | 当前输入快照上不存在缺失、命名问题、不能确认或被忽略问题 |
| `OUTDATED` | 报告仍可审计读取，但其输入指纹已不是案例当前输入，不能代表当前结果 |

## 实现者规则

- 枚举值、JSON 字段、表名和错误码均区分大小写，未经新的冻结任务不得改名或增加同义值。
- 示例中的 ID、时间、摘要和文件名是格式示例，不是默认业务数据。
- 本目录标为“待确认”的产品事实不得在实现中静默设为产品默认值。
- 安全硬限制可以采用可配置、拒绝优先的实现，但具体业务容量在确认前不得写成产品承诺。
- 任一实现若需要修改本契约，必须先形成单独的契约变更记录，再开始依赖该变化的代码。
