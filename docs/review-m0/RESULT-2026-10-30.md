# Review M0 手工流程与前端接入验收

创建日期：2026-10-30；验收完成日期：2026-10-31。状态：**本轮手工规则流程、前端接入及约定自动/真实运行验收通过；用户人工验收待进行**。

## 交付范围

本轮按用户决定实现 LOCAL_ONLY 手工规则确认流程：创建案例 → 录入并逐项确认规则 → 上传或选择自己拥有的材料 → 明确分配用途并确认上传完成 → 查看材料齐全性与命名报告 → 改逻辑名或补件 → 复审及下载副本。

入口为工作台“材料预审”，列表 `/review-m0`，详情 `/review-m0/:caseId`。规则与材料证据分开展示，原文件保留。忽略问题保留记录且不能把结果变成通过；旧报告绑定自己的清单快照，并显示是否过期。

官方依据可以管理，但自动抽取尚未接通。未处理依据会阻止发布正式清单，页面说明原因并允许移除案例引用；这不删除原文件。用户新增规则明确保留用户来源，不冒充官方自动识别结果。

## 本轮修复的真实缺口

1. 后台任务原来没有生产队列轮询入口，真实任务一直排队。新增受持久化开关控制的 worker，复用既有租约、取消与恢复机制，限制失败重领次数。新服务自动完成原排队任务，没有另造案例或手工改成功。
2. 后台执行没有浏览器 JWT，无法重新核验材料。新增独立服务凭据控制的只读内部文件通道，逐次核验文件归属，网关不公开此路径。
3. 发布后可能读到更旧草稿；页面也错误地用已发布修订判断是否存在草稿。现在读取最新修订并保留生命周期，仅允许发布最新候选。
4. 页面原先使用旧上传接口，生成没有预审 owner 信息的文件，加入案例失败。改用 owner-aware 上传，补当前账号的服务端分页文件列表；不推断或回填旧文件归属。
5. 流式下载在异步分发时丢失无状态认证上下文，引发响应已提交后的权限错误。已精准复现并修复为异步阶段重新校验原 JWT；专项测试由失败转为通过，真实浏览器下载与 B Probe 已通过。没有放开匿名异步请求或绕过文件归属检查。
6. 文件服务 SQL 调试输出暴露内部元数据。关闭这类输出，并用实际 MyBatis 查询和运行日志检查验证。
7. 真实浏览器修改逻辑文件名时返回 403：common 与 gateway 的 CORS 允许方法均漏了 PATCH。已补齐并验证带 Origin 的预检、实际修改及拒绝路径；真实浏览器改名和后续复审通过。保留原有来源限制，验收脚本没有绕开浏览器请求特征。

## 验收边界与下一步

本轮不调用外部模型、Embedding 或 Tavily，也没有以测试模型冒充自动抽取。未验证全部格式的 OCR、真实模型质量、生产容量或完整奖学金 V1 的资格、正文、事实及证明支持性。

文件权限结论限定于 Review 使用的 owner-aware 及内部只读通道；旧文件模块保留原有兼容接口，本轮不宣称全站文件权限已统一改造。新环境需执行文件表 V002、配置独立内部服务凭据，再使用报告中的强制完整打包入口，不能直接复用未经核验的增量产物。

自动门保留 `AUTO_VERIFIED / MANUAL_PENDING`；用户本人尚未在本轮页面上作出人工验收。人工启动入口见前端分报告，可依次体验规则确认、材料分配、问题证据、整改复审和历史报告。官方文件自动提取是下一阶段候选，需另行讨论证据定位、人工确认与评测标准，本轮没有提前开发。
