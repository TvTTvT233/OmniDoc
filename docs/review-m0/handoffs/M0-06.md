## 3. 错误、身份、幂等与下载

### 3.1 错误与身份

- `ReviewM0ApiExceptionHandler` 只绑定 `ReviewM0Controller`，不会改变旧 Controller 的 HTTP 200/errorCode 语义。
- 映射覆盖冻结枚举中的 400、401、404、409、415、503、500；请求级 415（错误 Content-Type）仍返回四字段并使用 `REVIEW_M0_REQUEST_INVALID`。冻结错误表没有 422 或 429 的 `errorCode`，因此未发明对应映射。
- `requestId` 由 Review M0 专用 once-per-request filter 生成并在同一请求中复用。
- `details` 只产生安全的 `resourceType`；不传正文、objectKey、预签名 URL、堆栈、SQL 或凭据。
- 系统/存储/文件/模型问题映射为 503/500 或 Job FAILED；测试验证系统失败不会写报告或业务 finding。

### 3.2 幂等

- 同步写通过 `ReviewM0ApiIdempotency` 在业务写事务中调用 M0-02 `ReviewM0IdempotencyStore`；业务前置门失败会回滚 claim，不错误占 key。
- digest 只包含规范化客户端字段；不会混入当前 case/revision/材料/清单等服务器快照。
- endpoint、owner、case 和 key 由 `IdempotencyScope` 隔离；同 scope/key 不同客户端载荷返回 409。
- Job 创建继续委托 M0-02/M0-05 submission service，保留原始 202/重放状态、并发唯一创建和事务语义。

有一项必须明确保留为上游兼容缺口：现有 M0-02 idempotency SPI/表只持久化 `responseStatus,responseType,responseId`，不持久化不可变响应 JSON。M0-06 可以按 ID 重放资源并保留首次状态，但对于之后会继续变化的资源（case、basis、preview、source、material、assignment、Job），无法在重启后严格返回“首次响应的逐字段快照”。在禁止修改 M0-02 idempotency/db 的范围内，没有添加旁路表或复制 SPI。建议最小兼容新增：由 M0-02 为完成记录增加有大小上限、版本化、完整性摘要保护的 `response_json`（或等价 blob 引用）并在同一事务写入/读取；M0-06 随后只需把 replay loader 改为反序列化该快照。当前实现不能据此宣称“服务器状态变化后仍逐字段重放原响应”已完全闭合。

### 3.3 下载

- 以 `materialId` 进行 owner/case/material/source 定位；普通材料只打开目标文件，ZIP 只打开 digest-bound 目标条目。
- `Content-Disposition` 使用当前 `submissionFileName`，同时生成 ASCII fallback 和 RFC 5987 `filename*`；CR/LF、引号、分隔符、路径与控制字符由上游 M0-04 安全构造拒绝/规范化。
- 不改原字节、`originalFileName`、`objectKey` 或文件服务元数据。
- 生产 gateway 不可用返回 503，不返回假字节。

## 4. 生产组合与启动约束

入口配置为 `com.javaee.aiservice.review.m0.config.ReviewM0Configuration`，组合：

- M0-02：既有 `ReviewCaseStore`、报告/Job/idempotency store、迁移初始化、dispatcher、submission service、handler registry；
- M0-03：`JdbcChecklistStore`、`OfficialBasisService`、`ChecklistService`、privacy store/service、remote consent verifier、extraction handler；
- M0-04：archive typed limits、formal content inspector、ZIP inspector/opener、material lifecycle/download；
- M0-05：input provider、regex matcher、deterministic engine、evidence factory、report reader/assembler、review executor/submission、decision service、formal/incremental handlers；
- M0-06：Controller、DTO mapper、错误/requestId、同步 idempotency wrapper和 fail-closed adapters。

registry 注册且启动验证恰好三类 handler：`CHECKLIST_EXTRACTION`、`FORMAL_REVIEW`、`INCREMENTAL_REVIEW`。缺失、重复或非法 typed limit 会 fail-fast。没有接入 `AgentExecutionService`/`AgentToolRegistry`，没有复制上游 Job 类型。

`LOCAL_ONLY` 默认上下文不创建 `RemoteCandidateClientFactory` 或远程客户端；P-08 未确认前没有默认供应商/模型配置。Review 专用属性前缀为 `ai.review-m0.runtime`，只承载 archive/regex typed limits；未修改公共 `application*.yml`。上游独立迁移开关仍使用冻结的 `ai.review-m0.persistence.*`。

生产恢复仍有一个上游最小兼容点：M0-02 dispatcher 的 acquire 查询不领取 `CANCEL_REQUESTED` Job，当前测试通过 M0-02 store 的 `finalizeCancellation(...)` 验证持久化取消终态；若要求进程重启后自动收敛取消，应在 M0-02 dispatcher/store 增加对 `CANCEL_REQUESTED` 的安全终结扫描，不应在 M0-06 复制调度状态机。
