### 2.1 文件事实与 fail-closed owner 边界

- `OwnedFileByteSource` 是唯一安全原语：实现者必须以认证 owner 对 `fileId` 做真实所有权证明，并把字节流原子绑定到不可变快照。
- `FileArtifactSnapshot` 固定保存 `fileId`、`originalFileName`、声明类型、大小、内容 SHA-256、存储版本和可用性。
- `VerifiedReviewM0FileAccess` 在流读完时复核大小、SHA-256 和读前/读后快照；跨 owner/不存在统一隐藏，服务不可用和源不可用保持冻结差异。
- 现有文件服务没有可靠的 fileId owner 证明，所以本包只提供 `FailClosedOwnedFileByteSource`；它明确返回服务不可用。没有调用 `permitAll` 文件端点，没有信任 raw `X-User-Id`，没有用 bucket 名或直连 MinIO 伪造安全集成。
- 生命周期测试记录并比较原字节、原文件名、声明元数据、存储版本、内容摘要和 objectKey；附加、确认、审查准备、逻辑改名、分配及下载不改变这些事实。

### 2.2 材料生命周期和事务

- 顶层 PDF、DOCX、XLSX、JPG、PNG 各形成一个材料；ZIP 只形成提交源和独立叶子材料，ZIP 容器本身永不成为材料。
- 顶层非白名单抛冻结 `REVIEW_M0_UNSUPPORTED_FILE_TYPE`（M0-06 映射 415）。白名单的加密、损坏、解析不足、类型不一致、源不可用等深度问题保存为 `CANNOT_CONFIRM` 诊断，不包装成 `MISSING`。
- 未确认当前清单/材料修订前，`requireReviewReadyOwned` 先拒绝且不读取源文件，不能生成 `MISSING`。
- 附加、移除、源事实漂移推进 `MATERIAL_SET`；逻辑改名推进 `NAME`；分配替换推进 `ASSIGNMENT`。Review 表写入和 M0-02 `advanceRevisionOwned` 均加入同一个 `REQUIRED` 事务；测试覆盖中途失败整体回滚。
- 材料集修订使旧上传确认失效；材料、分配和逻辑名修订使旧当前报告在同一事务内 `OUTDATED`。源摘要在审查准备时发生漂移也会先持久化 `SOURCE_FILE_UNAVAILABLE`、原子推进材料修订并拒绝旧确认；新修订重新确认后稳定返回该诊断，不重复推进修订。
- 所有查询和写入包含 owner 条件；异主附加、读取、改名、确认、分配和下载表现为不存在且没有成功侧信道。

### 2.3 ZIP 安全容器

- `ZipArchiveInspector` 使用流式、单遍、有界读取；只保留每个叶子的固定元数据和 SHA-256，不无界物化全部展开内容。
- `ZipArchiveEntryOpener` 按稳定 NFC 路径和预期摘要只流式返回目标条目；目标读完后继续验证 ZIP 的其余条目，因而后置危险条目也会使本次读取失败。
- 拒绝：嵌套 ZIP、非白名单叶子、路径穿越、Unix 绝对路径、盘符/UNC、反斜杠、NUL/控制字符、`.`/`..` 段、重复 NFC 路径、加密条目、损坏/CRC/条目摘要错误。
- 安全失败发生时不发布任何部分材料；ZIP 源仅保留安全诊断。

### 2.4 逻辑副本名和单份下载

- `submissionFileName` 只写 Review 材料记录；不修改 `originalFileName`、objectKey、文件服务元数据或源字节。
- 复用冻结 `LogicalFileName`：Unicode NFC、叶子名、类型后缀一致；拒绝 CR/LF、NUL、控制字符、路径分隔符和点目录。
- `Content-Disposition` 同时提供安全 ASCII fallback 与 RFC 5987 UTF-8 `filename*`；引号、百分号和非 ASCII 均安全编码，不允许响应头注入。
- `MaterialDownloadService.openOwned` 只以 `materialId` 定位：普通材料返回该源原字节，ZIP 材料只返回目标叶子，不返回 ZIP 容器或其他条目；同名材料仍由不同 `materialId` 正确区分。
- 本任务没有 Controller；M0-06 负责认证 principal、HTTP 状态和流式响应映射。

## 7. M0-05 / M0-06 可依赖入口

### M0-05

1. `MaterialLifecycleService.requireReviewReadyOwned(ownerId, caseId)`：上传确认前 fail-fast；成功时返回稳定 `MaterialCollectionSnapshot`，包含 sources、materials、assignments、diagnostics 和当前确认。
2. `MaterialLifecycleService.getSnapshotOwned(ownerId, caseId)`：owner-aware 管理视图，不执行正式审查。
3. `SubmissionMaterial` 的 `contentDigest`、`normalizedEntryPath`、`entryIndex` 和 `formalFileType` 是 ZIP 叶子稳定 identity；ZIP 容器不是材料。
4. `InputDiagnostic` 中的冻结原因供 M0-05 生成 `CANNOT_CONFIRM`；存在未决诊断时不得转写成 `MISSING`。

### M0-06

1. 组合 `JdbcReviewM0MaterialRepository`、`MaterialLifecycleService`、`MaterialDownloadService`；本任务刻意没有把两个 service 标成 Spring bean，防止在安全文件适配器缺失时被意外接入生产。
2. 认证 principal 规范化为 owner 后才能调用所有 `*Owned` 入口；不得新增无 owner 或管理员旁路。
3. `MaterialDownloadService.openOwned` 返回 `DownloadPayload`（content type、长度、Content-Disposition、InputStream）；Controller 只负责按冻结 HTTP 语义流式写出，不能重新定位对象或修改名称。
4. 只有满足第 5 节真实所有权契约的实现才能注入 `OwnedFileByteSource`；否则使用 `VerifiedReviewM0FileAccess.failClosed(...)` 并返回冻结服务不可用。
