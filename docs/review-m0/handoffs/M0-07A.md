## 状态语义

| 状态 | 含义 | 允许退出码 |
| --- | --- | --- |
| `ASSET_VERIFIED` | schema、合成 fixture、门禁脚本和 selector 契约自检通过；没有执行生产行为 | `0`，仅默认 Asset 模式 |
| `PENDING_INTEGRATION` | Asset 自检通过，但生产 adapter、精确测试选择或静态扫描边界未准备好 | 非零；当前为 `2` |
| `AUTO_VERIFIED` | selector 为 `READY`，15 个精确目标全部执行且未跳过，集成 evidence 全部通过，冻结的 15 个 P0 机器计数为 0，静态检查通过 | `0`，仅 Integrated 模式 |

资产、测试、报告、evidence 或静态门禁执行失败时直接非零退出，且不保留一个伪装成有效验收状态的机器报告。

`ASSET_VERIFIED` 和 `PENDING_INTEGRATION` 的机器报告均强制 `finalAcceptance=false`、`manualStatus=NOT_READY`。`AUTO_VERIFIED` 才允许 `finalAcceptance=true`，并要求 `readinessMissing=[]`、全部冻结 P0 计数为 0；不能以“测试类存在”“源码命中”或资产 fixture 通过替代生产行为验证。

## 资产结构

- `scripts/review-m0/run-m0-acceptance.cmd/.ps1`：统一入口；只运行精确测试类并从清理后的 Surefire XML 核对 suite/testcase 计数。
- `scripts/review-m0/assert-no-sensitive-data.ps1`：扫描 Git 可见文本、合成 fixture 和机器报告；Integrated 时额外扫描 selector 声明的生产根，并拒绝直接记录 `original/objectKey/contentHash/ocrText/documentContent` 的日志模式。
- `review-m0-p0-fixtures.json`：合成、无真实用户数据的 15 个 P0 目标 fixture manifest。
- `review-m0-fixture.schema.json`：fixture manifest schema。
- `review-m0-acceptance-report.schema.json`：机器报告和三态门禁契约。
- `review-m0-integrated-evidence.schema.json`：未来集成 adapter 的无正文聚合 evidence 契约。
- `review-m0-integration-selector.schema.json` 与实例：生产命名无关的后续适配边界。
- `ReviewM0*ContractTest`：资产、P0 fixture、状态、selector 和静态门禁契约测试；集成复跑计数以本批交接为准。

当前 selector 故意保持：

```text

adapterId=null

```

生产实现合入后，由集成任务仅按实际类名适配 `review-m0-integration-selector.json`：

2. 列出精确 JUnit FQCN；
3. 将 `M0-P0-001` 至 `M0-P0-015` 分别映射到精确 `className + methodName`；
4. 声明无绝对路径、无 `..` 的仓库相对生产扫描根；
5. 由被选测试向 `review.m0.acceptance.evidence.path` 写入不含正文的聚合 evidence。

门禁对 selector 和 evidence 逐层使用精确属性白名单；任何未声明字段、目标缺失、未执行/跳过目标、非零 P0 机器计数、额外/缺失测试 suite 均失败，不会降级为通过；正文与凭据由独立静态门扫描。
