## 6. 契约冲突与后续事实入口

### 契约冲突

没有发现冻结文档之间的新冲突。发现的是冻结目标与当前生产实现的明确缺口：

- M0-04 不能把当前 `download(fileId)`、元数据 `getMetadata(fileId)` 或 raw `X-User-Id` 当作 owner-aware 文件适配器。
- M0-03 不能把 XLSX 原始字节 fallback、图片字符串/空串、ZIP 原始解码当成结构化解析能力。
- M0-06 可复用现有 HTTP 状态/`errorCode,message` 风格，但 Review 契约必须补齐 `requestId,details`，且不得修改现有公共载体来制造兼容性副作用。
- M0-02 不能把 memory V001/V002 当作 Review schema；它们只证明当前 initializer 启动机制与 H2/MySQL-mode 测试形态。

### M0-02 可依赖的事实入口

1. owner 的稳定来源是认证成功后的 principal：JWT `Long userId` 经 `RequestUserContext` 规范为非空字符串；缺失认证必须失败。
2. ai-service 已有 `spring-jdbc`/MySQL driver，测试已有 H2；真实 schema 启动范式是 `InitializingBean + ResourceDatabasePopulator + 启动校验`。
3. 当前 H2 测试精确使用 `jdbc:h2:mem:<name>;MODE=MySQL;DB_CLOSE_DELAY=-1;DATABASE_TO_LOWER=TRUE`；迁移需在真实 MySQL 8 再做集成验证。
4. `ai.memory.schema.auto-migration.enabled` 默认 false；Review schema 必须拥有独立迁移开关/资源和独立表，不能偷偷复用 memory V001/V002。
5. 机器可读状态矩阵和 `CurrentJdbcMigrationBaselineTest` 是 M0-02 的直接事实入口；`PendingImplementationContractTest#reviewSchemaMustHaveAnIsolatedMigrationPath` 是目标边界，不是现有能力。
