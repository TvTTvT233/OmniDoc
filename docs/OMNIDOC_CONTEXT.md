# OmniDoc 项目上下文

## 文档目的

本文档记录 OmniDoc 已确认的长期产品定位、能力边界和当前阶段，供需求、设计、开发与验证共同使用。

本文档不是运行验收报告。“保留已有能力”表示产品与演进方向，不代表这些能力已经在当前环境完成启动、联调或端到端验证；实际状态以 `docs/PROGRESS.md` 及后续验证记录为准。

## 产品定位

OmniDoc 定位为：

> 通用文档智能工作台 + 多场景文档审查 Agent 平台

产品由两个相互复用的层次构成：

1. **通用文档智能工作台**：承载文档全生命周期和通用智能处理能力。
2. **多场景文档审查 Agent 平台**：在通用能力之上，按专业场景组合规则、材料证据、审查流程和人工确认节点。

首个专业场景为**奖学金申报材料审查**，V1 服务于准备申报本专科生国家奖学金的高校学生。

## 保留的通用能力

后续演进应保留并复用以下已有能力方向：

- 文件管理；
- 文档解析；
- 文档编辑；
- 版本管理；
- RAG；
- 通用 Agent；
- 工具调用；
- 审批；
- Trace；
- PPT。

以上清单用于约束产品范围和避免重复建设。各能力在目标运行环境中的可用性、完整性和接口契合度，仍需在运行基线验证阶段逐项确认。

## 场景扩展原则

- 专业审查场景建立在通用平台之上，不另建割裂的文件、文档、检索或 Agent 基础设施。
- 优先复用已有的 `AgentExecutionService`、`AgentToolRegistry`、RAG 和文档能力。
- 审查结果应可追溯到规则依据和材料证据。
- 信息不足时进入人工确认，不以模型推断替代缺失事实。
- 对原始材料采用非破坏性处理，建议、批注或派生结果与原件分离。
- 场景规则、材料证据、模型建议和人工决定应保持可区分，便于审计与迭代。
