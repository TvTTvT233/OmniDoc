# 分段接口 403 修复验收

验收日期：2026-10-17。实现与主要测试完成于10月16日，17日恢复环境并收尾。仓库 `D:\OmniDoc`，分支 `integration/core-baseline`，起始提交 `05c2d63`。主协调结论：本轮分段读取403修复通过验收。

## 修复内容

原先，同一份用户有权读取的文档，因为尚未生成 RAG 索引、Redis 中没有索引归属记录，被分段接口错误返回 HTTP200 / 业务403。本轮用真实文档权限和 Redis 记录关联复现了这一问题。

现在先用已验证的登录身份检查原文档访问权限，再读取分段存储。新增的权限检查接口不信任用户自行填写的 `X-User-Id`，也不返回文档正文。

| 情况 | 现在的行为 |
| --- | --- |
| 有文档读权，尚无索引记录 | HTTP200，明确返回 `NOT_INDEXED`，页面显示“当前文档尚未索引” |
| 有文档读权，属于当前用户的分段完整可读 | HTTP200，返回 `SEGMENTS_AVAILABLE` 和实际分段 |
| 未登录 | HTTP401 |
| 文档不存在或没有文档读权 | HTTP404，不返回正文 |
| 文档可读，但索引属于其他用户 | HTTP403，不返回分段 |
| 分段数据残缺、暂不可验证或读取期间变化 | HTTP409，页面提示分段不完整或暂不可读 |
| 权限服务、数据库或 Redis 不可用 | HTTP503，不伪装成未索引或空结果 |

分段可读不等于向量化完成。前端仍兼容旧的数组响应，但不会把旧空数组推断为“尚未索引”。

## 边界与后续

- 本轮不调用外部模型、Embedding或Tavily，不新增自动索引，不合并Review M0。未重跑与本次修改无关的M07完整门禁。
- 该接口现在要求存在真实active文档并通过文档ACL；只有独立RAG记录、没有文档实体的旧数据会404。协作者不能自动读取其他用户私有索引，管理员也没有该端点的索引归属豁免。
- 合法的“整文向量、无分段列表”路径可能返回409，含义是无法提供可验证的分段列表，不能据此断言向量索引损坏。
- 这是分段读取的修复，不代表其他RAG端点、旧文档接口的身份请求头兼容逻辑、自动重索引或文档/索引版本一致性均已修复。
- 旧工作台“AI已就绪”标记语义、文档修改后的索引一致性仍待后续讨论。真实模型链路、生产静态托管和性能容量未在本轮验证。
- 仍在本地候选分支，未更新 `main` 或推送远端。
