# 本地运行基线与真实服务验证

日期：2026-10-14（Asia/Shanghai）。起点为 `integration/core-baseline` / `ca3423a`，实际运行包含本轮 MCP 构造器注入修复，最终候选提交由主协调记录。

本轮是用户选择的**无需外部模型基线**：真实 MySQL、Redis、RabbitMQ、MinIO 和应用 HTTP；聊天模型、Embedding、远程摘要、远程重排、Tavily 不作为成功能力。不存在返回模拟答案或模拟向量的服务。Review M0 未合入。

## 2. 可复现启动步骤

以下在仓库根目录 PowerShell 7 执行，先确认 Docker Desktop 的 Linux engine 正常。HTTP 验证脚本使用 PowerShell 7 的 `-Form` / `-SkipHttpErrorCheck`，不能原样用 Windows PowerShell 5.1 运行。

```powershell
Set-Location D:\OmniDoc
Get-Command java, node, docker
docker version
docker compose version
$env:JAVA_HOME = (Resolve-Path .local/tools/zulu17.64.17-ca-jdk17.0.18-win_x64).Path
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
./mvnw.cmd -B -s .mvn/settings-local.xml -DskipTests package
```

上面的 JAVA_HOME/PATH 只作用于当前进程。JDK 目录是本次下载的便携运行时；迁移到其他机器时准备 JDK17 并替换路径，不要假定系统 Java 已符合版本。构建命令会明确跳过测试；回归需要执行 regression 文档中的独立命令。

```powershell
# 仅首次初始化执行；已有文件时脚本拒绝覆盖，防止遗失现有卷对应的密码。
./scripts/baseline/Initialize-Runtime.ps1
docker compose --env-file .local/baseline-runtime/runtime.env -f scripts/baseline/compose.yml config --quiet
docker compose --env-file .local/baseline-runtime/runtime.env -f scripts/baseline/compose.yml up -d
# Qdrant 仅在专项验收需要时加入。
docker compose --env-file .local/baseline-runtime/runtime.env -f scripts/baseline/compose.yml --profile qdrant up -d qdrant
docker compose --env-file .local/baseline-runtime/runtime.env -f scripts/baseline/compose.yml ps
```

初始化生成本地随机基础设施凭据，保存在被 Git 忽略的 `.local/baseline-runtime/runtime.env`。不要提交或展示其值。该文件不含模型凭据。SQL 初始化仅在空 MySQL 卷首次运行：user、file_metadata、document 及其关联表由仓库 SQL 建立；AI 启动通过显式 `AI_MEMORY_SCHEMA_AUTO_MIGRATION_ENABLED=true` 在这个隔离数据库执行 V001/V002。它不是生产数据库迁移流程，不应指向已有业务库直接运行。

健康确认（不要仅看容器进程存在）：

```powershell
docker exec omnidoc-baseline-20261014-mysql-1 sh -c 'MYSQL_PWD=$MYSQL_ROOT_PASSWORD mysqladmin ping -uroot --silent'
docker exec omnidoc-baseline-20261014-redis-1 sh -c 'REDISCLI_AUTH=$REDIS_PASSWORD redis-cli ping'
docker exec omnidoc-baseline-20261014-rabbitmq-1 rabbitmq-diagnostics -q ping
(Invoke-WebRequest http://127.0.0.1:19000/minio/health/live).StatusCode
(Invoke-WebRequest http://127.0.0.1:16333/healthz).StatusCode
```

```powershell
$baselineJava = Join-Path $env:JAVA_HOME 'bin/java.exe'
# 默认四个非模型服务：user / file / document / gateway。
./scripts/baseline/Start-Services.ps1 -JavaPath $baselineJava
# 显式关闭外部模型，只验证 AI 服务中的数据库/API/错误反馈能力。
./scripts/baseline/Start-Services.ps1 -JavaPath $baselineJava -Services ai-service -NoExternalModels
```

启动脚本检查 JDK17、产物和端口。已有端口占用时拒绝复用未知进程；仅启动 Hidden 子进程，不把“已创建进程”打印为健康成功。启动记录位于 `.local/baseline-runtime/processes.json`，每次标准输出/错误日志独立保存。文档/AI启动需要等日志出现 Started 后再做 HTTP 验证。

`NoExternalModels` 使用独立 YAML：四个模型 `enabled=false`，API 地址为回环拒绝端口，Embedding key为空，远程重排/摘要/MCP关闭。模型名带点的 Map key 使用方括号保留原名；首版未带括号时有三个开关未绑定，启动日志立即发现并停止修正，期间未发起模型请求。修正后启动日志与 `/api/ai/models` 均确认四模型 `available=false`。当前进程未发现会覆盖配置的 `AI_MODELS*`、`SPRING_AI*`、DASHSCOPE、OPENAI 或 TAVILY 凭据变量。本模式不适用于真实 RAG 验收；本轮不调用 Embedding API。

未来真实模型模式必须单独配置本地 `ProviderEnvFile` 或进程变量 `DASHSCOPE_API_KEY` / `OPENAI_API_KEY` / `OPENAI_BASE_URL`，重新启动并重新验收；默认脚本不会暗中生成占位密钥。不要把其他机器的数据库配置混入仅用于模型的配置文件。

## 3. 本轮真实验收结果

| 口径 | 实际结果 | 证据 / 边界 |
| --- | --- | --- |
| B01 配置与说明 | 本机环境、镜像、启动、迁移、端口、停止方法已记录 | 新机器从零复现尚未另行执行 |
| B04 依赖与服务 | 5个真实依赖可响应；5个应用完成启动 | AI 采用显式 NoExternalModels；Nacos未启动 |
| B05 身份/文档 | HTTP 主链 **8/8** | gateway注册→JWT登录→TXT上传→创建解析全文比对→读取→保存→再读新版→旧版本存在 |
| B05 重启持久化 | **1/1** | 只重启 document-service 后，新登录读取同一文档新版内容准确；MySQL/MinIO卷未重建 |
| B07 会话生命周期 | HTTP **8/8** | 新建→列表→重新加载→空消息→归档→恢复→删除→404；真实MySQL/Redis |
| B07 禁用模型错误路径 | 实际执行并明确返回错误 | async job外层 `success` 表示消费完成，但业务 `result.status=error`，回答为“模型已禁用”；不能认作Agent成功 |
| B07 消息持久化 | AI服务重启后 **3/3** | 同一会话存在、USER消息恢复、ASSISTANT禁用模型提示恢复；仅2条公开消息，数据库4条结构化消息 |
| B06 RAG / B08真实MCP | **未执行** | 用户本轮不接外部模型；Qdrant合成向量专项另见regression，不等于真实Embedding问答 |
| B09 浏览器 | 由前端执行者独立记录 | API通过不能替代浏览器验收 |

文档第一次重启复核使用了长时间中断前的旧JWT，返回401；重新登录后通过。该情况记录为认证已过期后的重登录，不把401误报为内容丢失。

真实 AI 启动首先暴露 `McpToolCatalogAdapter: No default constructor found`；后端执行者为生产注入构造器添加 `@Autowired` 并让配置测试走真实Spring实例化，修复后8/8专项通过并重打JAR，随后本轮AI启动/会话HTTP完成。此缺陷说明单元测试和源码存在不能替代真实装配。

公开会话中的 ASSISTANT 内容是错误提示，不是模型生成的正常回答；本轮不验证摘要压缩、token预算的模型使用效果、工具规划质量、生成质量或执行中任务恢复。异步任务外层与业务层的状态必须同时检查。

## 5. 停止与恢复

```powershell
Set-Location D:\OmniDoc
# 只停止本脚本记录且PID/开始时间均匹配的Java进程。
./scripts/baseline/Stop-Services.ps1
# 可只停止一个服务，以便验证重启后的持久化。
./scripts/baseline/Stop-Services.ps1 -Services document-service
# 只停止本项目容器，保留全部卷；不要使用 down -v。
docker compose --env-file .local/baseline-runtime/runtime.env -f scripts/baseline/compose.yml --profile qdrant stop
```

停止脚本已实际用于 document-service / ai-service 的重启。首次检查发现 PowerShell7 将JSON日期自动转DateTime，字符串比较会误拒绝；已改为UTC ticks比较，保持PID复用保护。未进行全体服务停止，以便主对话继续浏览器验收。恢复用前文 `compose up -d` 和 `Start-Services`，不再次运行初始化。

## 6. 剩余边界

- 本轮只确认合成TXT的解析与保存，没有把DOCX、复杂PDF、扫描PDF、OCR和全部文档格式都算通过。
- MySQL/MinIO未执行本轮故障注入或数据卷重建恢复，不能称为备份/灾备验收；Qdrant重启属于专项独立证据。
- 非AI业务服务使用本地直连、回环绑定与独立卷，未验证生产Nacos、TLS、多副本、负载和容量。
- 已验证“会话历史可读”，没有验证“刷新恢复正在执行的任务”。
- 不更改用户原始文档、其他项目容器或全局软件配置；不提交远端，不合并main。
