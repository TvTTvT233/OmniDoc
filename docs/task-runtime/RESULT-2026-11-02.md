# 通用 Agent 恢复与副作用控制 V2

状态：2026-11-05 完成本轮范围的自动验收，等待用户验收。实施始于 11-02，保留原报告文件名。

起点：`integration/core-baseline / b6dab11`。用户授权进入下一阶段；不更新 main、不推送，不接入外部模型。两位子 Agent 完成审计后触发额度限制，root 接手实施与验收。

## 改变了什么

- 新增独立 JDBC 任务/操作账本和 V001 迁移，复用现有 DataSource 与事务管理器。数据库是新 Agent 的执行事实，Redis 保留兼容投影。旧 Memory V1–V2、Review V1–V3 不改写。
- 同步、异步和审批续接进入同一领取入口。固定计划在工具执行前保存；工具结果先持久化，再推进检查点，间隙中断时复用已记录结果。恢复保留消息幂等标识；审批产生独立稳定回复标识，避免覆盖审批前回复。
- `owner + clientRequestId` 合并相同提交，异载荷返回 409；调用方不提供该 ID 时生成新 ID，因此不能据此保证独立客户端重试会合并。Async 先提交数据库，Rabbit 仅唤醒，poller 可补偿丢失通知。普通非 Agent Async 沿用旧路径。
- 领取使用数据库行锁和递增 epoch；发送、检查点、完成均验证当前租约。租约及审批到期直接由数据库时间判断，避免 JVM/JDBC 时区影响；公开时间转换为 epoch。
- 工具发送前记录意图。已成功结果复用；只读工具有限重试；写入已发送但结果未确定时进入 `OUTCOME_UNKNOWN`，阻止自动重放、continue 和单步 retry。成功写入后业务判据不满足也不会因此重试写操作。
- 删除改为高风险正式审批；审批绑定 owner、run、step 和完整解析参数摘要，数据库保存令牌摘要。旧 Redis 审批改为 Lua 原子校验消费，补齐目标参数指纹。审批本身不声称实现跨服务 exactly-once。
- 会话最终删除事务同时 tombstone 对应任务并清除正文，后续读取不从旧缓存复活。显式取消使旧执行者失去提交资格，已经发出的远程请求仍可能完成。
- 不保存用户 JWT。后台需要文档服务用户授权时停在 `AUTHORIZATION_REQUIRED`，通过前台续接获取当前授权。
- 工作台显示恢复等待原因并支持重新获取确认。编辑器与全局助理接入新审批挑战；文档写入提案需要明确应用，核对目标、版本和当前未保存内容，并阻止同页面重复应用。

## 配置与兼容

```properties
ai.agent.recovery.enabled=true
ai.agent.recovery.schema-auto-migration=true
ai.agent.recovery.lease-millis=120000
ai.agent.recovery.poll-millis=5000
```

默认不开启新恢复模式。首次迁移可显式允许建表，后续建议关掉 auto-migration 并验证 schema。开关拼写或重复值无效时启动失败，防止悄悄使用旧执行模式。每次启动只传一份开关。

只保证启用后创建的 JDBC Agent 任务；旧 Redis 记录不自动转换成可恢复任务。启用后旧任务的执行续接需要重新提交；新任务单步 retry 返回明确 409，避免绕开操作账本。新旧公共协议端点继续使用 V1 DTO；JDBC 任务暴露检查点摘要，不补造完整事件历史。

## 实测发现并修正

1. 审批前后回复共用消息键导致保存冲突；现在独立审批回复标识，恢复仍保留原标识。
2. 空 documentId 键被误判为文档授权需求；改为检查有效值。
3. MySQL 重启随机端口变化导致首轮 verify 无法连接；runner 重新读取端口，原失败日志保留。
4. MySQL/JDBC 时区导致公开审批时间偏差；改为 SQL 时钟与 epoch，隔离实库重新验证。
5. 更新脚本重复追加开关导致恢复模式未启用，同请求产生两个任务；真实接口拒收该结果。启动参数去重，并新增无效开关启动失败保护。失败的合成任务仅执行文本统计。
6. 页面取消后仍展示旧状态；取消成功后重新读取当前任务状态。
7. 11-05 续接时 Docker 和五服务已经停止。恢复既有容器及服务后，首轮接口读取早于 AI 启动完成，失败保留为 `http-cold-start-first.json`；确认服务就绪，重建未过期的合成审批夹具并重启同包，最终 14+11 项通过。浏览器在服务重启期间也出现连接错误，未声称零控制台错误。

## 明确边界

- 不是完整 harness：真实任务评测、模型/提示词版本对照、token/费用预算仍未实施。
- `OUTCOME_UNKNOWN` 只提供停止与核对提示，本轮没有人工 reconciliation 写接口，不自动猜测远程结果。
- 没有跨服务 exactly-once、生产容量/多节点部署验收。中断窗口通过确定性异常和新执行实例测试；实际进程重启验证的是已完成结果与等待审批，不能写成实测杀进程中断所有工具。
- 未调用外部模型、Embedding 或 Tavily，未测真实生成质量。前端生成写入保护有确定性测试，本轮浏览器未使用真实模型生成后覆盖文档。
- HTML PPT 的 HTML 结果随工具结果保存；临时文件路径不承诺跨机器有效。
- 未覆盖旧 WS 权限统一治理、非 Agent Async 恢复、自动规则提取或完整奖学金 V1。
- 原始文件记录、文档和历史报告的保留核对通过，详见末次 `final-state.json`；该检查比较元数据及数量，不替代所有对象内容逐字节校验。机器验证不代替用户验收。

主要改动：`taskrun/recovery/`、独立 SQL、Agent 执行/审批/注册表、Async service/listener、会话删除联动、任务协议投影；web 的任务面板、审批与写入动作保护，以及对应测试。后续先验收这组边界，再进入真实任务评测与预算阶段。
