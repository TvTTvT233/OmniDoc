# 统一任务运行协议 V1 验收记录

状态：本轮实现与自动/本机运行检查通过；用户人工验收仍待进行。起点为 `integration/core-baseline / 3da0d24`，不更新 `main`、不推送。

## 交付行为

- 新增 `GET /api/ai/task-runs/{runId}`，统一 Agent、异步 AI 请求、Review 的运行标识、状态、步骤、工具调用、结果引用和能力说明。Review 附 `caseId`；所有者仅来自认证上下文，没有管理员旁路。缺认证 401、异主/不存在 404、格式错误 400、存储故障 503；公共响应不透传任务正文、context、工具参数/结果正文或令牌。
- Agent 在实际开始、每次工具尝试开始/结束、等待、正常结束和捕获执行异常时记录元数据；沿用原 TaskRegistry/Redis 快照，每次执行有独立 executionId，每次工具尝试有独立 toolCallId。事件与调用各保留最近 256 条，截断显式标记。旧快照不补造历史。
- 同一 trace 续接沿用 runId，Agent attempt 表示进入执行入口的次数，不是模型循环次数；Review attempt 沿用领取次数，Async 没有该事实则为 null。revision 只在同一来源/运行内有意义，不提供跨来源全局排序。
- Async job 在 Agent 创建 trace 后由服务器立即绑定，两侧均可查关联。保留旧 outer success 兼容语义；新协议把 inner error 映射为 FAILED，把 action_required/planned 映射为 WAITING_INPUT。历史 Async 结果表示当次返回，关联的 Agent trace 则表示该任务的当前快照，续接后两者不必拥有相同状态。
- 取消请求和取消完成分开；执行器实际确认取消后优先返回 cancelled，等待态可直接取消。单步 retry 在服务层先校验 owner/Conversation 和终态，记录独立工具尝试，但仍不重算原任务的最终回答。
- Review 直接读取原数据库 job、已存在的 INPUT_VERIFIED/REVIEW_COMPUTED 检查点和历史 resultRef。检查点类型为 CHECKPOINT_SUMMARY；不伪造工具调用、开始时间或事件历史。SUCCEEDED、M0_READY/M0_NOT_READY、CURRENT/OUTDATED 分别表示执行、业务结论、新鲜度。
- 工作台和 Review 共用 TaskRunPanel，支持执行中轮询、结果/步骤/调用/关联展示、失败重试与切换防旧响应覆盖。工作台/全局助理不再把所有正常 HTTP 返回提示为执行成功。旧业务接口和 Review 引擎保持原入口。

## 明确未交付的能力

这是统一协议与来源适配，不是统一耐久执行引擎。Agent Redis 仍允许本机内存降级；事件有界、无完整重放/全局序号；尚无通用租约、CAS、防重复副作用或审批令牌原子消费保证。跨实例运行、并发续接、崩溃恢复、故障性能和生产容量未在本轮验收。新快照 hook 会增加 Redis 写入，压力和故障时延留待可靠性阶段测量。

旧 Agent WebSocket 广播的访问控制和旧完整快照响应不属于本轮新查询 API 的隐私保证。新协议没有复用全局广播作为鉴权通道。官方规则自动提取、真实模型/Embedding/Tavily 评测、累计 token/费用预算均未开展；完整 Review 历史验收门未重复运行，不用本轮只读投影验证替代整个业务验收。

下一阶段应独立设计恢复与副作用控制，以本协议提供的身份/状态作为边界，并继续复用 Review 已有可靠执行经验。本轮不自动启动下一阶段。
