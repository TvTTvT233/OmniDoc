# Agent 运行预算 V1

范围是已有 JDBC Agent 执行链；不另建执行器，不改变确定性 Review 引擎。实现基于 `26a2127`，等待主协调集成和真实 HTTP 验收。

## 契约

| 项目 | 行为 |
| --- | --- |
| 工具调用 | 沿用 maxToolCalls，默认8，上限20；按持久 operation 的 attempt 累加，重试也消耗调用预算 |
| 累计重试 | 新增 maxRetries，默认8，允许0至40；所有 operation 的 max(attempt-1,0) 相加 |
| 时间 | 新增 maxDurationSeconds，默认86400，允许1至604800；从首次创建起算，包含排队、审批等待和恢复，不因重启重新计时 |
| 费用 | inputTokens/outputTokens/cost 为 null，usageStatus=NOT_MEASURED；不以0冒充真实测量 |

新增字段未传时不序列化，保持既有请求的幂等摘要兼容；显式更改预算属于更改请求，相同 clientRequestId 不能悄悄提高限制。非法新增预算参数返回 INVALID_RUN_BUDGET。

预算参数保存在原 request_json 中，用量来自原 ai_agent_operation，无新增计数表。任务行锁下先检查预算再记录 SEND_INTENT。同一租约重复的在途操作不重复发送；已成功操作复用结果且不再次扣费。每个操作原有的最多3次尝试限制仍适用。

超过限制使用 BUDGET_TOOL_CALLS_EXCEEDED、BUDGET_RETRIES_EXCEEDED、BUDGET_DEADLINE_EXCEEDED，停止新调度并保存 FAILED。存在未确认写入时优先保留 OUTCOME_UNKNOWN/WAITING_INPUT；不把不确定副作用包装成普通预算失败，不自动重放。

模型网关和上下文准备处检查截止时间；网关返回和任务返回再次检查。最终回答的备用总结不会吞掉预算异常。该时间预算是调度边界检查，不能中断已经发出的远程请求，不保证墙钟时间绝不越界。真实供应商计费、外部请求取消和生产多节点负载仍未验证。

轮询按 runId 分页检查等待/排队任务的过期状态，避免仅前200项被处理；完成的任务不会因后来超过截止时间改成失败。未知写入保留待核对。

统一任务视图增加 budget；JDBC Agent 标记 SUPPORTED，旧 Agent 为 NOT_SUPPORTED，Review/Async 为 NOT_APPLICABLE。面板展示调用次数、累计重试、截止时间及停止原因；本阶段不提供网页预算参数编辑器。
