### 3.1 根因证据

- **SEC-002 · 用户详情接口可匿名读取个人信息**
  - 根因/定位：gateway-service/.../AuthGlobalFilter.java:39 将 /api/users/** 整体加入白名单。
  - 修复建议：白名单只保留注册、登录等精确路径；用户详情必须鉴权并校验本人或管理员权限。
- **FIL-012 · 文件移动返回成功，但原 fileId 随后无法下载**
  - 根因/定位：根据接口结果和对象存储状态推断：移动后的对象路径与按 fileId 下载所依赖的元数据未保持一致。
  - 修复建议：将对象移动与元数据更新做成可回滚的一致性操作，并在返回成功前验证新对象存在且原 fileId 可解析。
- **COM-001 · 评论创建者被硬编码为 userId=1**
  - 根因/定位：document-service/.../CommentController.java:28、56 使用 Long userId = 1L。
  - 修复建议：从可信网关请求头或统一用户上下文读取当前用户，并覆盖创建、修改、删除全链路。
- **ANN-001 · 批注创建者被硬编码为 userId=1**
  - 根因/定位：document-service/.../AnnotationController.java:28、57、67 使用 Long userId = 1L。
  - 修复建议：改为统一用户上下文，并为创建、修改、删除增加所有权与共享权限测试。
- **AIF-004 · 文件版本列表返回业务码 500**
  - 根因/定位：日志显示 LinkedHashMap 无法强制转换为 FileVersionVO.VersionInfo，位置 FileVersionService.java:115。
  - 修复建议：为 Redis/JSON 反序列化使用明确类型信息或显式 DTO 转换，并补充缓存回读测试。
- **RAG-009 · 混合检索返回业务码 500**
  - 根因/定位：日志显示 KnowledgeBase.java:270 对不可变 Map 执行 put，引发 UnsupportedOperationException。
  - 修复建议：合并前复制为 new HashMap<>(result)，并覆盖 vector/BM25 两类结果来源。
- **RAG-010 · 混合检索重排返回业务码 500**
  - 根因/定位：与 RAG-009 同源：候选结果为不可变 Map，混合阶段写入 content/source 时异常。
  - 修复建议：修复可变副本后，为 hybrid 和 hybrid/rerank 增加端到端回归。
- **AIF-007 · 文件删除确认流程无法写入 Redis**
  - 根因/定位：日志显示 FileDeleteService.DeleteRequest 无可用 JSON 序列化器/属性，Redis 写入触发 SerializationException。
  - 修复建议：将 DeleteRequest 改为可序列化 DTO/record 或配置 Jackson 可见性，并补充真实 Redis 集成测试。
- **AI-005 · 无效模型代码被静默回退**
  - 根因/定位：服务未在调用前校验模型代码，实际行为表现为默认模型回退。
  - 修复建议：校验允许的模型枚举；无效值返回 400，并在响应中明确实际使用模型。
- **SEC-004 · 跨用户文件下载虽被拒绝，但错误语义为 HTTP 500**
  - 根因/定位：访问拒绝/对象不可见异常未映射为明确的权限或资源不存在状态码。
  - 修复建议：统一异常映射为 403 或防枚举的 404，并保持 JSON 错误结构。
