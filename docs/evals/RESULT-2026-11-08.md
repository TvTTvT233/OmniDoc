# 固定任务评测与基线对比 V1

状态：步骤1、2已实施并通过本轮自动验收。起点为 `integration/core-baseline / ea4c0ad`，本轮不推送、不合并 main、不启用 CI 或外部模型。

## 交付

- `evals/suites/` 固定30项合成任务：文档/引用10、Review M0 10、Agent 10。每项包含任务、初始状态、预期结果、禁止行为、关键性、精确JUnit入口及替身边界。
- `scripts/evals/evaluate.py` 提供 validate、run、accept、compare。复用既有生产组件及测试夹具，按模块执行精确方法；每次试验重建夹具，独立采集XML。没有新建平行Agent执行器。
- 根POM增加显式 `task-evaluation` profile，只隔离评测报告目录，不改变普通测试配置或生产功能。
- 报告关联代码commit/工作树摘要、任务集及测试辅助文件摘要、评分器摘要、运行模式、逐用例成绩、失败分类及耗时。模型用量与费用为null，业务runId没有提取时保持null。
- 基线须显式审核接收：匹配当前30项定义、评分器、原始XML摘要与逐项成绩，拒绝未知额外字段；独占创建防止同名覆盖。比较要求已审阅基线及内容摘要，禁止覆盖输入或基线目录。
- 未运行、跳过、重复结果、测试失败、Maven失败和执行中源码变化都不能产生通过。全部重复试验计入结果，关键失败不会被平均分掩盖；配置/任务集/评分器不同返回不可比。

最终基线为 `evals/baselines/deterministic-v1-normalized.json`，审阅者明确记为 codex-root，不冒称用户已完成业务人工验收。两次最终运行发生于未提交工作树，报告保留 `dirty=true` 与实际工作树摘要；不能只拿旧commit SHA冒称测试了旧源码。

前一版基线 `deterministic-v1.json` 及其30/30和重复60/60证据保留。收尾发现Git换行转换会误触发指纹变化，因此将源码摘要的LF/CRLF规范化；原始XML仍按字节核验。评分器变更后重新执行30项基线与60次候选试验，使用新名称接收，没有覆盖旧基线。各轮数字不相加为不同场景总数。

本轮修复了独立审查指出的实际缺陷：自报通过的任意JSON可被当作基线、额外字段可能带入公开基线、同名基线写入竞态、compare可覆盖基线、普通测试XML串用风险、运行中源码变化未被识别。初始结果和负向证据留在忽略目录，没有抹去历史或修改业务断言降低标准。

## 运行入口

```powershell
python -m unittest discover -s scripts/evals -p 'test_*.py' -v
python scripts/evals/evaluate.py validate
python scripts/evals/evaluate.py run --repeats 2 --baseline evals/baselines/deterministic-v1-normalized.json
```

需要JDK17与正确的JAVA_HOME。详细操作和新基线审核命令见 `evals/README.md`。本机本轮使用已安装的Python 3.12和JDK17，不把个人绝对路径写入公共启动配置。原始XML、日志和负向构造报告位于 `.local/evals/`，不提交。

## 边界与下一步

- 这是固定业务场景的确定性组件评测，不是自然语言任务理解、真实模型规划、真实RAG回答质量或真实HTTP完整流程的评分。任务集文字描述对应已有测试夹具，不是由模型执行这些文字。
- H2、Mockito、内存文件源与固定模型输出均逐项声明；模拟中断不等于杀进程实测。本轮没有外部模型调用、真实用户材料写入、生产数据库变更。
- Review首次合格审查与增量改名复审已覆盖，但没有把它们冒称连续缺件补件HTTP旅程。
- 测试耗时只作参考，没有设置性能门槛，也没有Token/费用预算。自动化评测触发、评测面板、模型裁判、留出集、真实服务适配器及生产runId提取留待后续。
- 接受后摘要检测意外修改，不是防本机攻击者伪造证据的数字签名。共享Maven编译产物仍要求不与其他构建并发执行。
- 后续先将本入口接无密钥PR检查，再单独讨论真实模型数据与预算；本轮没有自动创建或修改远端工作流。
