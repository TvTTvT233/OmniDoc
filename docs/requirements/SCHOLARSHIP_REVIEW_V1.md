# 奖学金申报材料审查 V1 需求

## 1. 基本信息

- **场景名称**：奖学金申报材料审查
- **版本**：V1
- **需求状态**：已冻结
- **目标用户**：准备申报本专科生国家奖学金的高校学生
- **产品位置**：OmniDoc 的首个专业文档审查场景

V1 为学生提供提交前的材料审查与整改辅助，不替代学校、评审机构或其他官方主体作出的正式认定。

## 2. 目标

基于申报规则与学生材料，形成可追溯、可执行的提交前审查结果，帮助学生发现资格、材料、填写、一致性和证明支持方面的问题，并获得内容改进建议。

## 3. 输入材料

V1 的审查输入包括：

1. 申报通知；
2. 填写说明；
3. 官方模板；
4. 已填写申请表；
5. 成绩和排名证明；
6. 获奖及成果证明。

系统不得假定未提供的材料或字段已经满足要求。材料缺失、内容不可识别或规则无法定位时，应在结果中明确标记为“人工确认”。

## 4. 输出范围

V1 输出应覆盖以下七个方面：

| 审查维度 | 输出重点 |
| --- | --- |
| 资格检查 | 根据已提供规则与材料判断可确定的资格条件；无法确定的条件转人工确认 |
| 材料完整性 | 对照通知、说明和模板检查应交材料、附件及必要信息是否齐备 |
| 填写规范 | 检查申请表与官方模板、填写说明之间可验证的格式和填写要求 |
| 跨材料一致性 | 检查申请表、成绩排名证明、获奖及成果证明中的相关事实是否一致 |
| 成果证明支持性 | 检查申报内容是否有对应证明材料支持，以及证明与所述成果是否可关联 |
| 内容质量建议 | 针对表达清晰度、结构、信息密度和可读性给出建议，并与确定性问题区分 |
| 提交前整改清单 | 汇总待补充、待修正和待人工确认事项，形成可执行的提交前清单 |

## 5. 结论与证据规则

### 5.1 确定性问题

一项问题只有同时具备以下两类信息时，才能作为确定性问题输出：

1. **规则依据**：来自申报通知、填写说明或官方模板的可定位要求；
2. **材料证据**：来自已填写申请表、成绩和排名证明、获奖及成果证明等输入材料的可定位事实。

输出时应让使用者能够识别规则来源、材料来源和二者之间的判断关系。只有规则没有材料事实，或只有材料差异但缺少适用规则时，不得包装成确定性结论。

### 5.2 人工确认

出现以下任一情况时，应标记为“人工确认”：

- 所需材料、页面、字段或附件未提供；
- 内容不可识别、含义不明确或无法可靠定位；
- 不同材料存在疑点，但现有规则或证据不足以形成确定性结论；
- 需要学校、评审机构或其他权威主体确认。

人工确认项必须说明缺少什么信息或需要确认什么问题，禁止猜测、补写或暗示未经材料支持的事实。

### 5.3 内容质量建议

内容质量建议属于改进性意见，应与资格不符、材料缺失、填写错误等确定性问题明确区分，不得把语言偏好表述为强制规则。

## 6. 结果组织要求

每个审查发现至少应包含：

- 发现类型：确定性问题、人工确认或内容质量建议；
- 涉及的审查维度；
- 结论或建议；
- 规则依据（适用时）；
- 材料证据（适用时）；
- 建议整改动作。

提交前整改清单应能回溯到对应发现，并区分必须修正、需要补充信息和需要人工确认的事项。

## 7. V1 明确不做

V1 不包含以下能力：

- 获奖概率预测；
- 印章真伪识别；
- 自动提交申报材料；
- 自动覆盖用户原始文件。

## 8. 验收原则

V1 需求实现的验收至少应确认：

- 七个输出维度均有明确处理结果；无可审查内容时也应说明原因；
- 每个确定性问题同时具备规则依据和材料证据；
- 信息不足的事项均进入人工确认，没有基于猜测补全事实；
- 内容质量建议与确定性问题清晰区分；
- 能形成可执行、可回溯的提交前整改清单；
- 未引入本文件列明的 V1 范围外能力；
- 原始文件未被自动覆盖。

上述内容是需求验收原则，不代表当前代码已经实现或通过验证。
